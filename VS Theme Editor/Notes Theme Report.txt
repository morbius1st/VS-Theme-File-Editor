How to Read and Decode the Data Block
The Data block is a serialized binary stream. To parse it programmatically or manually, you must read the byte array sequentially according to its structural layout:
Header (First 24 Bytes)
The block begins with fixed metadata describing the data payload.
• Bytes 0-3 (4 bytes - Int32): Total Block Size. The total size of the data block in bytes, including the header and all subsequent category and color entries.)
• Bytes 4–7 (4 bytes - Int32): Header length. Usually 0b 00 00 00 (Version 11).
• Bytes 8–11 (4 bytes - Int32): Category Count. The number of distinct UI element categories (e.g., Text Editor, Environment) contained in this block.
• Bytes 12–27 (16 bytes - GUID): Theme Type / Base Theme GUID (e.g., the GUID for VS Dark, Light, or Blue base).
Category Blocks (Repeated based on Category Count)
Following the header, each category is packed sequentially:
• First 16 Bytes (GUID): Category GUID (e.g., Text Editor Category GUID: {7576B244-CC61-11D0-8754-00A0C911E8B2}).
• Next 4 Bytes (Int32): Color Entry Count. The total number of color definitions packed inside this specific category.
Color Entries (Repeated based on Color Entry Count)
Each individual color definition inside a category follows a rigid layout:
1. Name Length (4 bytes - Int32): The number of characters in the element name.
2. Name String (Variable length): The name of the UI token (e.g., Background, Keyword), encoded as a UTF-16LE (Unicode) string (2 bytes per character).
3. Color Data Types & Flags (4 bytes - Int32): Specifies which colors are valid (e.g., 0x01 for Foreground, 0x02 for Background).
4. Foreground Color (4 bytes - ARGB): The text color, stored in reverse byte order (B, G, R, A). If the foreground isn't utilized by this entry, it defaults to 00 00 00 00.
5. Background Color (4 bytes - ARGB): The background fill color, stored in reverse byte order (B, G, R, A).
